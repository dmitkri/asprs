# АСПиРС - Автоматизированная Система Поиска и Размещения Студентов

## Что это такое

АСПиРС - это система для управления студенческим кампусом.

Система состоит из трех частей:
1. **Веб-интерфейс** - для администраторов (воспитателей, администраторов)
2. **Telegram бот** - для студентов (получение QR-кодов, оплата, заявки)
3. **База данных** - хранит всю информацию

## Что можно делать в системе

### Для администраторов (через веб-интерфейс)
- Управлять данными студентов (добавлять, редактировать, удалять)
- Импортировать студентов из Excel
- Экспортировать данные в Excel
- Управлять комнатами и размещением студентов
- Управлять постельным бельем (создавать периоды выдачи, сканировать QR-коды)
- Организовывать мероприятия и отслеживать посещаемость
- Принимать заявки на ремонт
- Управлять оплатами проживания
- Создавать графики дежурств
- Работать с несовершеннолетними студентами

### Для студентов (через Telegram бот)
- Получать QR-коды для получения белья
- Получать QR-коды для мероприятий
- Оплачивать проживание через QR-код
- Подавать заявки на ремонт
- Смотреть свои заявки
- Смотреть график дежурств (если староста)

Подробнее про бота: [Документация Telegram бота](templates_docs/TELEGRAM_BOT.md)

## Что используется в проекте

### Backend (серверная часть)
- **Python 3.10+** - основной язык программирования
- **Flask 2.3.0+** - веб-фреймворк для создания сайта
- **SQLite** - база данных (файл `aspirs.db`)
- **python-telegram-bot 20.0+** - библиотека для работы с Telegram ботом

### Библиотеки для работы с данными
- **pandas** - для работы с Excel файлами
- **openpyxl** - для чтения и записи Excel
- **qrcode** - для создания QR-кодов
- **reportlab** - для создания PDF документов
- **Pillow** - для работы с изображениями
- **pyzbar** - для сканирования QR-кодов с фото

### Frontend (интерфейс)
- **HTML5/CSS3** - разметка и стили
- **JavaScript** - для интерактивности
- **Bootstrap 5** - для красивого интерфейса

## Как запустить проект

### Шаг 1: Установка Python

Убедитесь, что у вас установлен Python 3.10 или новее:
```bash
python3 --version
```

Если Python не установлен, скачайте его с [python.org](https://www.python.org/downloads/)

### Шаг 2: Установка зависимостей

Откройте терминал в папке проекта и выполните:
```bash
pip install -r requirements.txt
```

Это установит все нужные библиотеки.

### Шаг 3: Настройка переменных окружения

Создайте файл `.env` в корне проекта со следующим содержимым:
```
SECRET_KEY=ваш_секретный_ключ_здесь_любые_символы
TELEGRAM_BOT_TOKEN=ваш_токен_бота_от_BotFather
```

**Как получить токен бота:**
1. Найдите в Telegram бота [@BotFather](https://t.me/BotFather)
2. Отправьте команду `/newbot`
3. Следуйте инструкциям
4. Скопируйте токен и вставьте в `.env`

**SECRET_KEY** - это случайная строка для безопасности. Можете сгенерировать так:
```bash
python3 -c "import secrets; print(secrets.token_hex(32))`
```

### Шаг 4: Инициализация базы данных

При первом запуске база данных создастся автоматически. Но можно инициализировать вручную:
```bash
python3 -c "from database import init_db; init_db()"
```

**Что происходит при инициализации:**
- Создаются все таблицы в базе данных
- Создаются стандартные роли (super_admin, admin, vospitatel и т.д.)
- Создается первый администратор (логин: `admin`, пароль: `admin123`)
- Применяются миграции (если база уже существует)

### Шаг 5: Запуск веб-приложения

Запусти Flask приложение:
```bash
python3 app.py
```

Или:
```bash
flask run
```

По умолчанию сайт будет доступен по адресу: `http://127.0.0.1:5000`

**Первые учетные данные:**
- Логин: `admin`
- Пароль: `admin123`
- **Важно:** При первом входе нужно будет сменить пароль!

### Шаг 6: Запуск Telegram бота

Откройте новый терминал и запустите бота:
```bash
python3 telegram_bot.py
```

Бот начнет работать и отвечать на сообщения студентов.

**Важно:** Бот и веб-приложение должны работать одновременно!

## База данных

Система использует SQLite - это файловая база данных. Все данные хранятся в файле `aspirs.db` в корне проекта.

### Основные таблицы

#### employees (Студенты)
Главная таблица со всеми студентами:
- `id` - уникальный номер студента (PRIMARY KEY)
- `fio` - ФИО студента (обязательное поле)
- `phone` - номер телефона
- `group_name` - учебная группа
- `birth_date` - дата рождения
- `photo` - путь к фотографии
- `notes` - заметки о студенте
- `absences` - информация об отсутствиях
- `reprimands` - замечания
- `vacation` - информация об отпуске
- `vacation_history` - история отпусков (JSON массив)
- `extra_data` - дополнительные данные (JSON объект)
- `building`, `entrance`, `room_number` - адрес проживания (корпус, подъезд, комната)
- `tg_username` - Telegram username
- `room_occupancy` - количество проживающих в комнате (по умолчанию 1)
- `payment_from_scholarship` - оплата из стипендии (1) или нет (0)
- `can_do_rounds` - может делать обходы (1) или нет (0)
- `is_round_chief` - является старшим студентом (1) или нет (0)
- `is_entrance_elder` - является старостой подъезда (1) или нет (0)
- `education_level` - уровень образования
- `has_own_bed_linen` - есть свое постельное белье (1) или нет (0)
- `max_entrances` - максимальное количество подъездов для воспитателей
- `is_local` - местный студент (1) или нет (0)
- `is_minor` - несовершеннолетний (1) или нет (0)

#### admins (Администраторы)
Данные администраторов системы:
- `id` - уникальный номер (PRIMARY KEY)
- `username` - логин для входа (UNIQUE, обязательное поле)
- `password_hash` - зашифрованный пароль (обязательное поле)
- `role` - роль (super_admin, admin, vospitatel, audit, razmeshenie)
- `permissions` - JSON с правами доступа (по умолчанию '{}')
- `created_at` - дата создания (автоматически)
- `is_active` - активен (1) или заблокирован (0)
- `fio` - ФИО администратора
- `password_changed` - пароль был изменен (1) или нет (0)
- `max_entrances` - максимальное количество подъездов

#### roles (Роли)
Настройки ролей и их прав:
- `name` - название роли (PRIMARY KEY)
- `permissions` - JSON с правами доступа (обязательное поле)
- `description` - описание роли

#### events (Мероприятия)
Информация о мероприятиях:
- `id` - уникальный номер (PRIMARY KEY)
- `admin_id` - кто создал мероприятие (обязательное поле, FOREIGN KEY на admins)
- `admin_fio` - ФИО создателя (обязательное поле)
- `location` - место проведения (обязательное поле)
- `description` - описание мероприятия (обязательное поле)
- `event_date` - дата проведения (обязательное поле)
- `event_time` - время начала (обязательное поле)
- `created_at` - дата создания (автоматически)
- `coauthor_id` - ID соавтора (FOREIGN KEY на admins)
- `coauthor_fio` - ФИО соавтора
- `organizers` - список организаторов (текст)

#### event_locations (Места проведения мероприятий)
Список мест для мероприятий:
- `id` - уникальный номер (PRIMARY KEY)
- `name` - название места (UNIQUE, обязательное поле)
- `description` - описание места
- `created_at` - дата создания (автоматически)
- `created_by` - кто создал (FOREIGN KEY на admins)
- `is_active` - активно (1) или нет (0)

#### event_attendance (Посещаемость мероприятий)
Кто посетил какое мероприятие:
- `id` - уникальный номер (PRIMARY KEY)
- `event_id` - какое мероприятие (обязательное поле, FOREIGN KEY на events)
- `employee_id` - какой студент (обязательное поле, FOREIGN KEY на employees)
- `student_fio` - ФИО студента (обязательное поле)
- `scanned_by_tg_id` - Telegram ID того, кто зарегистрировал
- `scanned_by_username` - username того, кто зарегистрировал
- `scanned_at` - когда зарегистрировался (автоматически)
- UNIQUE(event_id, employee_id) - один студент может быть зарегистрирован на мероприятие только один раз

#### tg_users (Telegram пользователи)
Связь Telegram аккаунтов со студентами:
- `tg_user_id` - ID пользователя в Telegram (PRIMARY KEY)
- `tg_username` - username в Telegram
- `employee_id` - связь со студентом (FOREIGN KEY на employees)

#### bed_linen_qr_codes (QR-коды для белья)
Временные QR-коды для получения белья:
- `id` - уникальный номер (PRIMARY KEY)
- `qr_code` - сам код (UNIQUE, обязательное поле)
- `employee_id` - для какого студента (обязательное поле, FOREIGN KEY на employees)
- `tg_user_id` - кто создал код (обязательное поле, FOREIGN KEY на tg_users)
- `created_at` - когда создан (обязательное поле)
- `expires_at` - когда истекает (обязательное поле, обычно через 5 минут)
- `used` - использован (1) или нет (0)

#### bed_linen_dates (Периоды выдачи белья)
Периоды, когда можно получать белье:
- `id` - уникальный номер (PRIMARY KEY)
- `start_date` - дата начала периода (обязательное поле)
- `end_date` - дата окончания периода (обязательное поле)
- `created_at` - дата создания (автоматически)
- `is_active` - активен (1) или нет (0)

#### scans (Сканирования белья)
Записи о сканировании QR-кодов для получения белья:
- `id` - уникальный номер (PRIMARY KEY)
- `employee_id` - какой студент (FOREIGN KEY на employees)
- `token` - токен сканирования
- `scanned_at` - когда отсканировано
- `period_id` - период выдачи белья (FOREIGN KEY на bed_linen_dates)
- UNIQUE(employee_id, token) - один студент не может использовать один токен дважды

#### bed_linen_tokens (Токены для белья)
Временные токены для получения белья:
- `id` - уникальный номер (PRIMARY KEY)
- `token` - сам токен (UNIQUE)
- `created_at` - когда создан

#### maintenance_requests (Заявки на ремонт)
Заявки студентов на ремонт:
- `id` - уникальный номер (PRIMARY KEY)
- `employee_id` - кто подал заявку (обязательное поле, FOREIGN KEY на employees)
- `tg_user_id` - Telegram ID студента
- `student_fio` - ФИО студента (обязательное поле)
- `building`, `entrance`, `room_number` - адрес студента
- `message` - описание проблемы (обязательное поле)
- `status` - статус (new, in_progress, completed, по умолчанию 'new')
- `request_number` - номер заявки (например: MR-A1B2)
- `assigned_admin_id` - кто взял в работу (FOREIGN KEY на admins)
- `assigned_admin_fio` - ФИО администратора, взявшего заявку
- `admin_comment` - комментарий администратора
- `created_at` - дата создания (автоматически)
- `assigned_at` - когда назначена
- `closed_at` - когда закрыта

#### dormitory_payments (Оплаты проживания)
Информация об оплатах проживания:
- `id` - уникальный номер (PRIMARY KEY)
- `employee_id` - кто оплатил (обязательное поле, FOREIGN KEY на employees)
- `tg_user_id` - Telegram ID студента (FOREIGN KEY на tg_users)
- `amount` - сумма оплаты
- `payment_date` - дата оплаты
- `payment_month` - за какой месяц (формат: YYYY-MM)

## Роли в системе

### super_admin (Супер администратор)
- Полный доступ ко всему
- Может управлять администраторами и ролями

### admin (Администратор)
- Доступ ко всему кроме управления администраторами
- Может редактировать, удалять, импортировать

### vospitatel (Воспитатель)
- Может редактировать студентов
- Управляет бельем, мероприятиями, комнатами
- Не может управлять оплатами

### audit (Аудит)
- Доступ только к разделу оплат

### razmeshenie (Размещение)
- Только просмотр студентов и отчетов

## Как работать с проектом

### Добавление нового студента
1. Войдите в систему как администратор
2. На главной странице нажмите "Добавить студента"
3. Заполните форму
4. Сохраните

### Импорт студентов из Excel
1. Подготовьте Excel файл с данными студентов
2. В админке нажмите "Импорт Excel"
3. Выберите файл
4. Нажмите "Импортировать"

### Создание мероприятия
1. Перейдите в "Календарь мероприятий"
2. Нажмите "Добавить мероприятие"
3. Заполните форму (место, описание, дата, время)
4. Сохраните

### Управление местами проведения
1. В меню администратора выбериье "Места проведения мероприятий"
2. Нажмите "Добавить место"
3. Введите название и описание
4. Сохраните

## Решение проблем

### Бот не отвечает
- Проверьте, что бот запущен (`python3 telegram_bot.py`)
- Проверьте токен в `.env` файле
- Проверьте интернет-соединение

### Не могу войти в систему
- Проверьте, что база данных создана
- Попробуйте использовать стандартные данные: admin/admin123
- Если не работает, пересоздайте базу данных

### Ошибка при импорте Excel
- Проверьте формат файла (должен быть .xlsx или .xls)
- Убедитесь, что в файле есть нужные колонки
- Проверьте логи в `logs/app.log`

### Страница не открывается
- Проверьте, что Flask приложение запущено
- Проверьте порт (по умолчанию 5000)
- Проверьте логи на наличие ошибок
